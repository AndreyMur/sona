# Plan: Sona — голосовой учёт личных финансов (MVP v1.0)

**PRD:** prd-project.md
**Дата:** 29.09.2026

## Фазы реализации

### Фаза 1: Backend — self-hosted прокси к OdiRouter на aidailyplanner.ru (Docker)

**Цель:** Единый рабочий канал распознавания речи и разбора текста в структуру операций на собственном сервере; выбор моделей по цене/качеству до разработки UI.
**Затрагивает:** backend
**Задачи:**
- [x] Endpoint STT-транскрипции: модели `gpt-4o-mini-transcribe` (основная), `gpt-4o-transcribe` (Pro), `whisper-large-v3` (fallback)
- [x] Endpoint NLU-разбора: `gemini-3.8-flash` (основная), `gpt-4o` (fallback при confidence < 0.7), ответ по `response_format: json_schema`
- [x] Версионируемый системный промпт в конфиге + обновление через remote config без релиза
- [x] Аутентификация приложения (токен устройства), rate limiting, лимиты расходов, обработка ошибок и retry, логирование задержки и стоимости
- [x] Docker-деплой прокси на `aidailyplanner.ru` (HTTPS) + прогон тестового набора из 50 фраз; метрики WER, точность категоризации, средняя задержка и стоимость
**Когда готова:** Прокси развёрнут на `aidailyplanner.ru`, аутентификация и лимиты расходов работают, все 50 фраз обработаны, выбраны модели STT/NLU, endpoints стабильно отдают JSON по схеме операций (тип, сумма, категория, подкатегория, дата).

### Фаза 2: Frontend — Tracer Bullet: голос → сохранённая операция

**Цель:** Минимальный рабочий путь от голосовой фразы до операции в локальной БД.
**Затрагивает:** frontend / database
**Задачи:**
- [x] Локальная БД (Drift + SQLCipher): таблицы операций, категорий, подкатегорий
- [x] Запись аудио `.m4a` (16 kHz, mono) + запрос разрешения на микрофон
- [x] OdiRouter-клиент (Dio + interceptors) и сохранение разобранных операций
- [x] Экран записи: состояния Ожидание → Слушаю → Распознал → Разобрал → Сохранено; подтвердить / изменить / отменить
- [x] Тесты сквозного пути: одна фраза с несколькими тратами создаёт несколько операций, время ≤ 3 сек
**Когда готова:** Голосовая фраза создаёт сохранённую операцию за ≤ 3 сек; фраза с двумя тратами создаёт две операции; операции можно подтвердить, изменить и отменить.

### Фаза 3: Frontend — ручной ввод, шорткаты, офлайн-парсер

**Цель:** Работа приложения без голоса и без сети.
**Затрагивает:** frontend
**Задачи:**
- [x] Ручной текстовый ввод с AI-разбором через OdiRouter
- [x] Локальный fallback-парсер (регулярки + словарь 300–500 категорийных слов)
- [x] Бейдж «Офлайн-разбор» + кнопка «Уточнить через AI» после появления сети
- [x] Голосовые шорткаты «Баланс», «Сколько на продукты», «Отмена»
- [x] Тесты: ручной ввод, офлайн-разбор, работа шорткатов
**Когда готова:** Текст «кофе 450» разбирается как голос; без сети операция сохраняется локальным парсером с бейджем; шорткаты выполняют соответствующие действия.

### Фаза 4: Frontend — онбординг, главная, категории

**Цель:** Полноценный вход в приложение и быстрый запуск к микрофону.
**Затрагивает:** frontend
**Задачи:**
- [ ] Онбординг из 4 слайдов: выбор валюты, категорий, разрешения на микрофон и пуши
- [ ] Категории и подкатегории по умолчанию (16 категорий) + ручная корректировка и обучение категоризации
- [ ] Главная: приветствие, карточка баланса, кнопка «Сказать», быстрые действия, последние операции, мини-прогресс бюджета, совет дня
- [ ] Deep link: тап по иконке → микрофон уже пульсирует
- [ ] Тесты: прохождение онбординга, отображение главной, deep link
**Когда готова:** Новый пользователь проходит онбординг и попадает на главную; тап по иконке открывает экран записи с пульсирующим микрофоном.

### Фаза 5: Frontend — бюджет, лимиты, уведомления

**Цель:** Контроль лимитов без таблиц и своевременные предупреждения.
**Затрагивает:** frontend
**Задачи:**
- [x] Месячный бюджет + лимиты по категориям и подкатегориям (#21)
- [x] Настраиваемые пороги 50/80/100%, прогноз до конца месяца, опция переноса остатка (#23)
- [x] UI: карточка бюджета, пончик-диаграмма, список категорий с прогрессом (#25)
- [x] Push-уведомления: 50/80/100% лимита, превышение, ежедневное напоминание, еженедельный отчёт, аномалии трат (#26)
- [x] Тесты: расчёт лимитов и порогов, срабатывание уведомлений (#28)
**Когда готова:** Лимиты и пороги считаются верно, срабатывают push-уведомления на 50/80/100% и при превышении.

### Фаза 6: Frontend — аналитика

**Цель:** Наглядная статистика трат по периодам.
**Затрагивает:** frontend
**Задачи:**
- [ ] Табы Неделя / Месяц / Год / Период
- [ ] Сумма трат и % к прошлому периоду
- [ ] Бар-чарт по месяцам и топ категорий
- [ ] Фильтры по категориям и периодам
- [ ] Тесты: корректность агрегатов, переключение табов, фильтры
**Когда готова:** Аналитика показывает суммы, % к прошлому периоду, бар-чарт и топ категорий по выбранному периоду и фильтрам.

### Фаза 7: Frontend — профиль, безопасность, приватность

**Цель:** Управление данными и защита личного доступа.
**Затрагивает:** frontend
**Задачи:**
- [ ] Профиль: аватар, имя, email, скоринг «Финансовое здоровье» (0–100), меню (данные, счета, категории, уведомления, безопасность, подписка, выход)
- [ ] Защита входа: PIN / Face ID / Touch ID + автоблокировка
- [ ] Опция «Только ручной ввод» — работа полностью локально, без отправки аудио в облако
- [ ] Экспорт и удаление данных одной кнопкой
- [ ] Тесты: вход по биометрии/PIN, автоблокировка, режим «Только ручной ввод», экспорт/удаление
**Когда готова:** Данные хранятся локально с шифрованием, вход защищён PIN/биометрией, работает опция «Только ручной ввод» и удаление данных.

### Фаза 8: Frontend — монетизация Sona Pro

**Цель:** Freemium-модель и подписка.
**Затрагивает:** frontend / backend
**Задачи:**
- [ ] Интеграция `in_app_purchase`: подписка 349 ₽/мес и 2 490 ₽/год
- [ ] Пробный период 7 дней + восстановление покупок
- [ ] Ограничение бесплатного тарифа: 30 операций/мес, 1 бюджет, базовая статистика (лимит проверяется на стороне прокси)
- [ ] Настройка «Качество распознавания: Стандарт / Максимум (Pro)» + приоритетная обработка
- [ ] Тесты: оформление, восстановление, снятие ограничений, проверка лимита 30 операций
**Когда готова:** Подписка оформляется и восстанавливается, пробный период работает, бесплатный тариф ограничен 30 операциями, Pro снимает ограничение.

### Фаза 9: Дизайн-система, темы, локализация, доступность, производительность

**Цель:** Единый визуальный язык, темы и соответствие нефункциональным требованиям.
**Затрагивает:** frontend
**Задачи:**
- [ ] Тема: светлая / тёмная / системная, цвета по палитре, типографика Inter/Manrope, волновая анимация Rive
- [ ] Локализация интерфейса на русский (RU)
- [ ] Доступность: Dynamic Type, VoiceOver / TalkBack
- [ ] Производительность: запуск ≤ 1.5 сек, размер приложения ≤ 60 МБ
- [ ] Тесты: переключение тем, проверка локализации, доступности и замеров запуска/размера
**Когда готова:** Доступны светлая и тёмная темы, интерфейс на русском, работают Dynamic Type и VoiceOver/TalkBack, запуск ≤ 1.5 сек и размер ≤ 60 МБ.
